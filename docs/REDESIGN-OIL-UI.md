## 1. 这轮怎么做的

按 Oil UI 的**显式对比流程**执行：

1. 先固定产品事实与真实文案；
2. 先列删除清单，再谈风格；
3. 每个方向只保留一个主角与一个主动作；
4. 用灰阶骨架确认构图，而不是先铺颜色；
5. 同一内容、同一视口、同一状态，统一截取日间 / 夜间；
6. 给出推荐，但把决定权留给用户。

没有先改代码，也没有把三个方向做成“同一张卡片换三种颜色”。三个方向的**骨架、字体气质、信息密度和主动作位置**都不同。

## 2. 产品事实（三案共用，不再发挥）

- 产品：Draftly，中文优先的 AI 写作工作台。
- 当前页：`写作风格画像`，属于六个写作模块之一。
- 输入：参考文本；支持 TXT / DOCX / PDF；单份上限 12,000 字；最多 8 份；合计 40,000 字。
- 分析：六个维度——`语气特征`、`用词习惯`、`句式特征`、`表达方式`、`段落结构`、`修辞特征`。
- 输出：可编辑的画像、推荐写作指令、避免项、可信程度 `较高 / 一般 / 有待调整`。
- 保存：本地 SQLite；最多 20 份画像；可在润色器中选择使用。
- 边界：只分析语言表面特征，**不判断作者身份、写作水平或事实正确性**。
- 主动作：`重新分析`；次动作：`保存画像`；后续动作：在润色中使用。

## 4. 三个方向

### A. 讲义 / Lecture Notes

> **一句话**：像一本被认真批注的课程讲义——每个判断都写在页边，可以逐条核对。

- **骨架**：244px 课程目录侧栏 + 主工作表 + 300px 页边批注栏。
- **主角**：六维画像；**主动作**：右上角实心钴蓝 `重新分析`。
- **记忆点**：右侧页边批注，用衬线斜体写“先看依据，再看结论”，把分析变成可读的旁注。
- **字体**：Georgia / Palatino + 宋体作标题与引文；Segoe UI / 微软雅黑作界面。
- **色彩**：钴蓝墨水 + 粉笔白 + 冷灰绿；没有第二个装饰色。
- **适合**：需要覆盖六个模块、保持侧栏导航效率的全站方案。
- **风险**：最稳，也最接近“精致的效率工具”；如果想彻底摆脱上一版气质，它的突破性不如 B。

### B. 校样 / Proof（推荐）

> **一句话**：像一张还在校对的印刷校样——文字是主角，朱红只标记判断与证据。

- **骨架**：去掉侧栏；报头导航 + 双页校样。左页是参考文本节选（带行号、红笔标记），右页是画像、六维、写作指令和可信度印章。
- **主角**：左边正在被阅读的文本；**主动作**：顶部朱红 `重新分析`。
- **记忆点**：右页底部的 `可信程度 / 中` 印章，以及左边页边的朱红句长批注。红色只出现在“判断 / 证据 / 主动作”，不做装饰。
- **字体**：正文全部衬线（Georgia / Palatino / 宋体），界面标签用无衬线；比例更接近书页，而不是后台。
- **色彩**：马尼拉纸 + 铁胆墨 + 朱红；夜间变成“夜校样”，是暖黑而不是简单反色。
- **适合**：让 Draftly 一眼就像“写作工具”，而不是“AI 工具”；品牌页、编辑器、风格画像都受益。
- **风险**：没有常驻侧栏，六个模块要靠顶部导航；移动端需要另做一套模块切换。长文本页的行号与批注要控制密度。

### C. 案卷 / Dossier

> **一句话**：像一份可检索的研究案卷——结构先于装饰，每个判断都能回到出处。

- **骨架**：顶部模块标签 + 184px 档案元数据栏 + 中央特征表 + 286px 证据栏。
- **主角**：六维特征表；**主动作**：右上角深青 `重新分析`。
- **记忆点**：每条特征右侧的 `S01 ¶03` 证据引用，以及右栏的原文摘录；画像不是结论，而是可追溯的记录。
- **字体**：标题衬线，表格与元数据无衬线，编号等宽；信息密度最高。
- **色彩**：深青 + 赭石 + 冷灰档案纸；青色负责动作，赭石负责编号与元数据，角色分工明确。
- **适合**：如果产品核心卖点是“有依据的风格分析”，而不只是“生成一段画像”。
- **风险**：表格感最强，温度最低；对普通用户可能显得像专业工具。需要确保移动端不是把三栏硬压扁。

## 5. 对比结论

| 维度 | A 讲义 | B 校样 | C 案卷 |
| --- | --- | --- | --- |
| 第一眼 | 安静、可信、像课程材料 | 像一本书 / 一张校样 | 像一份研究档案 |
| 信息密度 | 中 | 中低，呼吸感最好 | 高，最专业 |
| 导航扩展 | 最好（常驻侧栏） | 中（顶部导航） | 中（顶部标签） |
| 品牌辨识度 | 中 | **最高** | 高 |
| 与“写作”的关系 | 讲课 / 学习 | **阅读 / 修改** | 研究 / 归档 |
| 落地风险 | 低 | 中 | 中高 |

**推荐：B 校样。**

理由不是“它更好看”，而是它最准确地回答了“Draftly 是什么”：

1. 左文右评的结构，就是风格画像这件事本身；不需要解释。
2. 文字是界面里最大的东西，符合写作工具的主体性。
3. 朱红只承担“判断 / 证据 / 主动作”，比多色系统更克制，也更像学术出版。
4. 夜间模式是“夜校样”，不是把日间颜色反过来；两种模式都保留纸张感。
5. 它主动打破了“侧栏 + 卡片 + 徽章”的 AI 产品默认脸。

补上首页后，这个判断更成立：B 的首页不是“产品截图 + 大标题”的 SaaS 模板，而是一张真正的头版——主张、校样、工具索引在同一套排版里成立。A 的首页更像一份可靠的课程说明，C 的首页更像一份研究档案；它们都可用，但只有 B 同时做到了“简洁、学术、像写作”。

如果优先考虑**全站六个模块的扩展效率与最低风险**，选 **A**；如果产品的核心叙事是**每个判断都可追溯**，选 **C**。

## 6. 可访问性与实现边界

- 三案正文均 ≥ 13px；B 的阅读文本 15px；C 的密集表格 11.5–12px，属于工具型密度，不用于长文阅读。
- 所有主按钮 ≥ 42px；A 为 44px；主题切换为 44×40 的可点击区域。
- 焦点环统一为 2px 实线 + 2px offset；静态图不可见，但 HTML 中已写入。
- 支持 `prefers-reduced-motion: reduce`；本轮没有加动画，避免用动效掩盖结构问题。
- 对比度（WCAG 2.1）：

| 方向 | 正文 / 纸面 | 次要 / 纸面 | 强调 / 纸面 | 按钮文字 / 按钮 |
| --- | --- | --- | --- | --- |
| A 日间 | 15.17:1 | 5.74:1 | 7.32:1 | 7.72:1 |
| A 夜间 | 15.32:1 | 8.11:1 | 8.66:1 | — |
| B 日间 | 15.15:1 | 5.88:1 | 5.88:1 | 6.26:1 |
| B 夜间 | 15.80:1 | 7.89:1 | 7.21:1 | — |
| C 日间 | 15.07:1 | 5.59:1 | 7.79:1 | 7.94:1 |
| C 夜间 | 16.04:1 | 8.21:1 | 8.63:1 | — |

> 所有正文与次要文字 ≥ 4.5:1；C 的赭石小字单独修正到 5.07:1（纸面）/ 4.72:1（次级纸面）。

## 7. 选中之后做什么

1. 把方向写成语义令牌：`--surface`、`--surface-raised`、`--text`、`--text-muted`、`--accent`、`--accent-contrast`、`--line`、`--focus`，日/夜各一套。
2. 加主题切换：默认跟随系统，手动选择写入 `localStorage`，首屏无闪烁。
3. 先改 `AppShell` / 导航 / 按钮 / 表单 / 空状态 / 错误状态，再改六个工具页。
4. 首页只保留一个主张、一个真实产品画面、一个主动作；不再做浮夸 hero。
5. 用真实任务重跑：导入样本 → 分析 → 改一条维度 → 保存 → 在润色器中选择 → 删除画像。
6. 验证 1440 / 1024 / 390 三档、键盘焦点、对比度、`prefers-reduced-motion`、构建与现有测试。

**本轮没有做**：交互、响应式、真实主题切换、首页的可运行改造、业务代码、测试与构建。首页与工作台目前都是静态视觉稿；它们要等方向选定后再实现。
