# Draftly 视觉改版提案

> 目标：去掉“AI 生成感”，建立简洁、学术、以绿色作点缀的视觉系统，并同时设计日间与夜间模式。
>
> 状态：**仅方案评审，尚未改动现有页面与设计令牌。** 选定方向后再落地到 `src/app/globals.css` 与各页面组件。

## 0. 先看什么

每张提案板同时展示两个高频场景：

- **左侧：日间首页** — 品牌语气、标题层级、工具入口与整体留白。
- **右侧：夜间工作台（风格画像）** — 复杂表单、分析结果、已保存画像在深色下的可读性。

这不是“首页亮 + 工作台暗”的固定搭配。每个方向都定义了完整的日间与夜间令牌，落地时两种主题会覆盖全站；提案板只是用一屏同时呈现两种模式，便于比较。

## 1. 三个方向

### 方案 A｜学报 Journal

![方案 A：日间首页与夜间工作台](../artifacts/redesign-proposal-a-journal.png)

**一句话**：像一份可阅读的学术刊物，而不是一个 AI 产品页。

- **视觉 DNA**：暖象牙纸、衬线大标题、编号索引、极细的分隔线、页码与旁注。
- **日间**：`#FBF9F2` 纸面 / `#F1EEE4` 页面底 / `#1C251F` 墨色 / `#2E6247` 林绿。
- **夜间**：`#121814` 底 / `#19201A` 纸面 / `#E9EDE5` 文字 / `#8DB99D` 浅绿。
- **字体**：标题 Iowan/Palatino/Georgia + 宋体回退；正文 Segoe UI / 微软雅黑；元数据 Cascadia Mono。
- **形状**：直角或 2px 微圆角；不用投影；层级靠字号、留白与 1px 规则线。
- **首页**：衬线主张 + “修改样张” + 两列工作索引。没有大号营销徽章、没有渐变球、没有悬浮卡片。
- **工作台**：左侧编号目录；输入、分析、画像按“步骤”排布；绿色只用于当前项、可交互元素与修改标记。
- **适合**：希望保留人文温度、面向学生 / 写作者 / 通识用户；从“AI 工具”转向“写作刊物”。
- **代价**：如果全站大量使用衬线，长界面会偏文艺；需要严格控制字号与行高，避免“杂志排版”压过工具效率。

### 方案 B｜研究台 Research Desk

![方案 B：日间首页与夜间工作台](../artifacts/redesign-proposal-b-desk.png)

**一句话**：把界面做成一张研究台，而不是一个聊天窗口。

- **视觉 DNA**：冷白纸面、瑞士网格、仪表式编号、无衬线大标题、数据化状态。
- **日间**：`#FFFFFF` 纸面 / `#E9ECE6` 页面底 / `#16201A` 墨色 / `#1E6A4A` 林绿。
- **夜间**：`#0F1512` 底 / `#151D18` 纸面 / `#E8EFE9` 文字 / `#7FBA9B` 浅绿。
- **字体**：Inter / Segoe UI / 微软雅黑；正文可保留 Newsreader 作阅读字体；Cascadia Mono 用于数字与状态。
- **形状**：4px 以内圆角；模块用边框网格，不用漂浮卡片；主按钮为实底绿，次按钮为描边。
- **首页**：无衬线大标题 + 右侧“编辑样张”（删除/新增/事实变更计数）+ 3×2 模块网格。
- **工作台**：顶部面包屑与自动保存；步骤条“输入 / 分析 / 使用”；分析结果为表格行，置信度只用 HIGH / MED / LOW。
- **适合**：希望最快摆脱“AI 味”，同时保留产品效率与专业工具感；面向研究者、编辑、专业人士。
- **代价**：更冷、更硬；如果品牌希望亲和，需要在文案与插图上补温度。也最容易与现有组件结构兼容。

### 方案 C｜档案 Catalogue

![方案 C：日间首页与夜间工作台](../artifacts/redesign-proposal-c-catalogue.png)

**一句话**：像使用一套编目系统：克制、干燥、所有信息都有出处。

- **视觉 DNA**：石灰纸、旧式衬线、等宽字段名、档案编号、强分隔线、方形印章。
- **日间**：`#F8F6EE` 纸面 / `#E7E4D8` 页面底 / `#191D19` 墨色 / `#315C43` 深绿。
- **夜间**：`#111512` 底 / `#181D18` 纸面 / `#ECEEE5` 文字 / `#91B99D` 浅绿。
- **字体**：标题 Georgia/宋体；界面 Segoe UI；字段与状态 Cascadia Mono。
- **形状**：全直角；不使用卡片阴影；用目录行、字段表、印章与细规则线建立层级。
- **首页**：目录式标题 + `FILE / 06` 风格画像档案卡 + 六行编目表。没有传统 hero 按钮，主行动是带下划线的文字链接。
- **工作台**：顶部极简导航；左侧 `RECORD / OWNER / SAMPLES / UPDATED` 元数据栏；右侧分析记录表；绿色只用于状态、印章与关键路径。
- **适合**：最强调“学术、可复核、非 AI”；面向研究、档案、出版、政策等严肃写作场景。
- **代价**：最有辨识度，也最硬；对休闲写作用户可能显得有距离感。落地时需要重排更多布局，不能只换颜色。

## 2. 横向比较

| 维度 | A 学报 | B 研究台 | C 档案 |
| --- | --- | --- | --- |
| 学术感 | 强 | 中强 | 最强 |
| 亲和度 | 高 | 中 | 低 |
| 工具效率 | 中 | 高 | 中 |
| 辨识度 | 高 | 中 | 最高 |
| 与现有结构兼容 | 中 | 高 | 低 |
| 改造工作量 | 中 | 小 | 大 |
| 主要风险 | 偏文艺、易变成杂志 | 偏冷、偏仪表盘 | 偏硬、门槛感强 |

### 推荐

- **综合首选：A 学报。** 它同时满足“学术、简洁、绿色点缀”，又保留写作产品需要的温度与可读性，适合作为 Draftly 的主视觉。
- **最去 AI 味：C 档案。** 如果目标用户明确是研究者、学术写作者，C 的品牌记忆点最强。
- **最稳落地：B 研究台。** 如果希望先快速全站换肤、保持现有信息架构，B 的迁移成本最低。

## 3. 共同规则（三个方向都遵守）

1. **绿色只做点缀**：主按钮、当前导航、焦点、关键状态、修改标记；不大面积铺绿。
2. **不用 AI 视觉套话**：渐变球、玻璃拟态、发光边框、sparkle 图标、超大圆角卡片、悬浮营销徽章全部去掉。
3. **层级靠排版**：字号、字重、留白、1px 规则线；卡片只在确实需要分组时使用。
4. **日间 / 夜间同时设计**：不是简单反色；夜间降低纯白发光，提高正文对比，保留绿色识别。
5. **可访问性**：正文对比度 ≥ 4.5:1（下表均 ≥ 5.6:1），可见焦点，点击目标 ≥ 44px，支持 `prefers-reduced-motion`。
6. **中文优先**：不引入外链字体，避免构建/国内网络失败；中文回退宋体或微软雅黑。
7. **不改变产品行为**：只改视觉系统与布局表达；API、SQLite、风格画像逻辑与现有测试保持不变。

## 4. 选定后的落地顺序

1. **令牌层**：在 `globals.css` 建立语义变量（背景 / 纸面 / 文字 / 次要 / 边框 / 主绿 / 浅绿 / 焦点 / 危险），加入 `[data-theme="dark"]`；用 `color-scheme` 与首屏内联脚本避免闪烁。
2. **主题切换**：日间 / 夜间 / 跟随系统三态；写入 `localStorage`，监听 `prefers-color-scheme`；切换按钮进入键盘 Tab 顺序。
3. **外壳与基础组件**：AppShell、Sidebar、MobileNav、PageHeader、按钮、输入框、Notice、分段控件、对话框。先统一形状、边框、焦点与间距。
4. **页面层**：首页 → 工具工作台 → 风格画像 → 反馈 / 法律页 / 管理后台。
5. **验收**：对比度脚本 + 键盘走查 + 1440 / 768 / 390 三档截图 + 现有构建与测试回归。
